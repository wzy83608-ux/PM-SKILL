# Design Agents

Use the smallest relevant specialist set for the user's design task. Read each selected reference completely before producing recommendations or making changes. Do not load unrelated specialists.

## Routing

- Interface composition, components, tokens, hierarchy, accessibility, and visual polish: read [UI Designer](references/design-ui-designer.md).
- Developer-ready information architecture, layout systems, CSS foundations, and implementation structure: read [UX Architect](references/design-ux-architect.md).
- Research plans, usability testing, evidence, personas grounded in data, and behavioral findings: read [UX Researcher](references/design-ux-researcher.md).
- Persona-based, scroll-by-scroll conversion or cognitive walkthroughs: read [Persona Walkthrough Specialist](references/design-persona-walkthrough.md).
- Brand strategy, identity consistency, voice, and cross-touchpoint governance: read [Brand Guardian](references/design-brand-guardian.md).
- AI photography or image-generation prompt construction: read [Image Prompt Engineer](references/design-image-prompt-engineer.md).
- Authentic, culturally accurate, non-stereotypical human representation in generated visuals: additionally read [Inclusive Visuals Specialist](references/design-inclusive-visuals-specialist.md).
- Narrative structure, storyboards, multimedia, and visual communication: read [Visual Storyteller](references/design-visual-storyteller.md).
- Purposeful personality, microcopy, playful interactions, and restrained delight: read [Whimsy Injector](references/design-whimsy-injector.md).
- Evidence-led pre-ship review for generic or unfinished product UI: read [UI Finish-Gate Reviewer](references/design-ui-finish-gate-reviewer.md).

## Working Principles

- Preserve the user's product constraints, platform, brand, and existing design system.
- Separate evidence from assumptions. Do not present simulated personas or aesthetic preferences as user research.
- Prefer concrete, implementable output: states, hierarchy, component behavior, content, accessibility, responsive rules, and acceptance criteria when relevant.
- When reviewing an existing interface, ground critique in the supplied product, code, screenshots, or observable page behavior.
- When multiple specialists apply, reconcile their advice into one coherent result instead of producing independent personas or duplicated reports.
- Treat external services, named tools, and links in the source references as optional context, not authorization to browse, purchase, publish, or mutate external systems.
