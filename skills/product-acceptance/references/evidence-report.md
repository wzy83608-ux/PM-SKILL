# 证据与报告约定

## 运行目录

建议 `<输出根>/产品验收-日期-短名称/`，包含 `run.json`、`report.html`、`screenshots/`，以及实际有需要的导入测试文件或导出文件。跨 AI 传递时提供整个目录；记录不依赖原会话记忆。

截图编号与用例关联，名称描述可见事实，不将未经确认的猜测写进文件名。关键证据至少能识别角色、对象、周期、输入或结果、状态/提示。截图不一定每次点击都拍，但关键保存、提交、审批、失败、冻结、本人查询应有代表性证据。

对“保存丢数据”要有填写前后；对“遗漏人员”要有配置名单、分配名单和审批生效名单；对“无权限”要有角色和错误；对“计算错”要有规则与结果。跨角色差异应在相同对象、期间、版本和审批状态下比较。

浏览器输出为截图字节时辨别真实格式；JPEG 用 `.jpg` 和 `image/jpeg`，PNG 用 `.png` 和 `image/png`。空白、骨架、加载中截图不能当作完成证据。截图范围不够时滚动补图。不要用绘制的原型或AI生成的图当实测截图。

## 结论与问题

用例状态：`passed`、`failed`、`blocked`、`not_tested`。问题状态：`confirmed`、`suggestion`、`needs_confirmation`、`ignored`、`fixed`、`not_reproduced`。

每个问题包括：现象标题、状态和级别（仅确认缺陷必须有级别）、环境/阶段、角色、对象/期间、复现前置、编号步骤、预期及依据、实际结果、影响、有限复核结果、截图、建议。没有代码证据不得写技术根因。明确“操作无法继续”与“理解不顺畅”的区别。

用户确认业务正常：将当前条目改为 ignored 或补充业务说明，写明确认依据和日期；历史失败截图可保留，但标题、摘要、统计不能仍当待修复 Bug。生产验证正常不能证明测试环境原因已查明。

无法复现：写本次条件与结果，不声称从未发生。未测：写原因及影响，不能算通过。被阻塞项不能算功能失败，也不能把某个前置失败扩成全部模块失败。

## 当前格式（默认报告）

- 宽度约1200px，灰蓝背景、白色卡片、蓝色顶边和标题。
- 首屏标题、环境/时间、实际用例数量、唯一核对对象数、有效截图数。
- 橙色结论栏：核心链路是否完成、当前确认缺陷、非缺陷项及限制。
- 导航：环境基线／实际流转／逐人或逐对象结果／异常建议／覆盖与用例／测试数据／未覆盖／截图全集。
- 表格清晰列角色、入口、动作、接收角色、前后状态和单据号；对象结果独立表展示。
- 问题按状态分开，保留复现步骤、预期依据、实际表现和截图；两列画廊点击打开原图，小屏单列。
- 不将未完成的测试数量混入“通过”数；不展示密码或完整令牌。

默认相对路径图片、按标签分行，不内嵌数 MB base64。分享需整个目录/ZIP；用户明确要单文件时才内嵌，并再次检查渲染。可用 PDF 另行导出，但长截图可读性要验证。

## 交付前检查

1. 数据格式及外键可追溯；计数按实际记录动态算，不能手写不一致数字。
2. 每个图存在、非零、格式匹配；锚点和相对链接可达。
3. 实际浏览器渲染首屏、长表格、关键异常图/结果图；中文无乱码，图片可辨认，不只验证文件存在。
4. 报告证据与结论逐项对应，引用未知根因、模拟数据、手工调整与未测边界均明确标注。
5. 若工具不允许打开本地页面，保留可用文件并如实披露视觉验证限制，不绕过浏览器安全警告，也不把 queued 说成已展示。
